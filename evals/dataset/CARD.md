Labelling protocol (each rule since the dataset version it first applies to):
- Labels were judged from `state` and the option descriptions alone, and were fixed before any model run. (since `1e1bb88d47f0`)
- `needs_review` is true exactly when `risk` is Medium or High, and `retry` is true only for `flaky` failures. (since `1e1bb88d47f0`)
- Drafts whose evidence fit two options were rewritten or dropped while authoring, before any run. (since `1e1bb88d47f0`)
- A label changes only when a reviewer finds it wrong on its merits, never because the model disagreed. A change to any item's state, media, questions, gold, or split alters the dataset's content hash, which each run records, so runs on different label sets cannot be compared by accident; annotations (kind, tier, source, rationale) do not. (since `1e1bb88d47f0`)
- Every `score` scale runs from least to most of the quantity its instruction names; index 0 is always the least. The expected score is read in those units. A scale is never reversed to make a label read naturally. (since `1e1bb88d47f0`)
- For a `noul` question, P(true) is the probability of the condition the instruction names; the condition is phrased so that `true` is the pole that calls for caution. (since `1e1bb88d47f0`)

Gold is single-rater human. Label stability was drafted by a blinded LLM panel (independent labels, the gold never shown); disagreements queue for the maintainer's adjudication. The model under test never labels.
