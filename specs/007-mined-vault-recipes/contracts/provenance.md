# Contract: source, register, and check for mined items

## `Source` (mined)

- Fields are exactly `artefact`, `commit`, `register_row` — no others (a foreign field raises).
- `commit` matches `^[0-9a-f]{40}$` (Pydantic `_HEX40` and again in `check.run`).
- `artefact` is the source-repo-relative note path.

## `RegisterRow` (used)

- Requires `snapshot`, `mirror`, and `transformation`; `mirror.sha256` must equal `snapshot.sha256`.
- For a `custom_permissive` licence, `permission` is required — the permission the source rests on.
- `attribution` is present (share-alike requires it; here it carries the grant credit).
- `items_imported` equals the number of items `register.validate` resolves to the row.

## `register.validate(rows, items)` (changed)

For every item whose `source.kind` is `mined`, a new branch (mirroring `imported`):

1. Its `source.register_row` must name a row — else a problem (`mined register_row … is not in the register`).
2. That row's `verdict` must be `used` — else a problem.
3. The row is counted so `items_imported` reconciles exactly.

A `mined` item with no row, or with a row that is not `used`, therefore fails `ember eval dataset check` (FR-004).

## `check.run` (unchanged, plus the above)

Keeps the mined-commit 40-hex check; inherits the register cross-check through `validate`. It also fails when the current content hash is not in `versions.lock` or when an item is not in `splits.lock`.

## Removal path (FR-015)

A revoked or narrowed permission: delete the affected items from the dataset, re-mine without them (or drop the source), then run `card` (records a new version) and `check`. No item survives a withdrawn `used` row.

## Data card

`card.json`/`CARD.md` carry the source, its licence reading, and the attribution (the register hash is embedded); regenerated by `ember eval dataset card`.
