# Contract: Long-context probe artifacts

**Feature**: `003-context-window-audit`
**Date**: 2026-10-09
**Scope**: The files a probe run writes, which a reviewer uses to recompute each model's
cap (SC-004, SC-006). Field definitions are in [data-model.md](../data-model.md).

## Layout

```
results/context/<run_id>/          # working output (gitignored)
  manifest.json                    # ProbeManifest, written before the first inference
  rows-flash.jsonl                 # one ProbeRow per inference, append-only
  rows-full.jsonl
  summary.json                     # ProbeSummary, derived; regenerated by --rescore

evals/context/runs/<run_id>/       # tracked copy of the run a decision cites (--snapshot)
```

`run_id` matches `^context_\d{8}T\d{6}Z$` unless `--run-id` sets it.

## Guarantees

- **Append-only rows.** Each row is flushed and fsynced as it is written. On resume, a
  torn last line is discarded, and rows already recorded for the same (model, item,
  length, depth) are skipped.
- **Derived summary.** `--rescore` rebuilds `summary.json` from the rows and the manifest,
  byte for byte. Serialization is fixed:
  - keys are sorted and indented by two spaces
  - floats are rounded to 6 decimals
  - rows are sorted by (model, length, depth, item)

  `summary.inputs_sha256` holds digests of the rows files and the manifest.
- **Rule parameters fixed in the manifest.** These are written before any inference:
  - tolerances: accuracy 0.02, Brier 0.02
  - memory budgets: flash 34,359,738,368 bytes, full 103,079,215,104 bytes (96 GiB; the
    maintainer raised full's from 64 GiB on 2026-10-10)
  - lengths and depths
  - length tolerance: 32 tokens
  - bootstrap: 10,000 resamples, 95%, seed 0
  - exploratory subset size: 48

  The summary applies these values and never redefines them.
- **Pinned inputs.** The manifest records:
  - the dataset path and SHA-256
  - the included item ids, and the excluded ones with reasons
  - the exploratory subset's item ids
  - the filler path and SHA-256
  - the model repo and revision
  - the device, dtype, and package versions
  - `git_hash` and `git_dirty`

  A canonical run requires `git_dirty: false`.
- **Reproduction.** `--reproduce ID` re-runs ID's inputs into a new run. It passes when:
  - counted tokens are identical for every row
  - every answer probability is within ±0.001
  - per-question correctness is identical
  - every model's cap verdict is the same (full reproductions only)

  A reproduction narrowed with `--items N` re-runs only the first N items and compares
  rows only. A subset can't reproduce the full run's statistics, so verdicts aren't
  compared. On any mismatch it exits 2 and lists the differences. The reproduction's
  manifest records the run it reproduces (`reproduces`), so a resumed reproduction still
  compares.

## Canonical run

A run cited by a decision record must meet all of these:
- It is a full run over every registered model: no `--smoke`, `--items`, `--lengths`, or
  `--models` subset.
- It completed: every worker finished (`completed: true` in the manifest).
- Its sizing gate passed.
- `git_dirty` is false.
- It is snapshotted into `evals/context/runs/`.

The decision note links the snapshot path and quotes each model's cap and first failure.
